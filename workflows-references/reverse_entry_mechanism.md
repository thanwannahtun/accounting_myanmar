### ၁။ Standard (နိုင်ငံတကာ စံနှုန်း) အရ နောက်ကွယ်က အလုပ်လုပ်ပုံ

Standard စာရင်းကိုင်စနစ်တစ်ခုမှာ "Reverse" ကို နှိပ်လိုက်တာနဲ့ မူလ မှားယွင်းနေတဲ့ စာရင်း (Original Entry) ဟာ ပျောက်မသွားပါဘူး။ ယင်းအစား နောက်ကွယ်မှာ အောက်ပါအတိုင်း အလိုအလျောက် အလုပ်လုပ်သွားပါတယ်-

1.  **စာရင်းအသစ်တစ်ခု မွေးဖွားခြင်း (Creates a New Entry):** စနစ်သည် ယနေ့ရက်စွဲ (သို့မဟုတ် ပြင်ဆင်လိုသော ရက်စွဲ) ဖြင့် Journal Entry အသစ်စက်စက် တစ်ခုကို အလိုအလျောက် ဖန်တီးလိုက်ပါတယ်။
2.  **Debit နှင့် Credit နေရာလွှဲခြင်း (Swaps Dr and Cr):** မူလ စာရင်းမှာ Debit သွင်းထားတဲ့ အကောင့်နဲ့ ပမာဏကို Credit ဘက်သို့ လည်းကောင်း၊ Credit သွင်းထားတဲ့ အကောင့်နဲ့ ပမာဏကို Debit ဘက်သို့ လည်းကောင်း အလိုအလျောက် နေရာ ပြောင်းပြန် လှန်ပစ်လိုက်ပါတယ်။
3.  **ချိတ်ဆက် မှတ်တမ်းတင်ခြင်း (Creates Audit Reference):** အသစ်ထွက်လာတဲ့ Reversal Entry ရဲ့ Description (သို့) ရှင်းလင်းချက်မှာ "Reversal of Journal Entry #XYZ" ဟု မူလစာရင်းကို အလိုအလျောက် ညွှန်းဆို (Reference) ထည့်သွင်းပေးပါတယ်။ 

**ရလဒ်:** စာရင်းနှစ်ကြောင်းစလုံး (မူလ အမှားစာရင်း နှင့် ပြောင်းပြန်လှန်လိုက်သော စာရင်း) သည် Ledger ထဲတွင် ကျန်ရှိနေမည်ဖြစ်ပြီး၊ ပေါင်းနှုတ်လိုက်ပါက အာနိသင် (Effect) သည် "သုည (Zero)" ဖြစ်သွားမည် ဖြစ်ပါသည်။ ထို့နောက်မှ အမှန်တကယ် လိုချင်သော စာရင်းအသစ်ကို Entry ထပ်လုပ်ရပါသည်။

### ၂။ ကျွန်တော်တို့ App အရ နောက်ကွယ်က အလုပ်လုပ်ပုံ (System Logic)

ကျွန်တော်တို့ ရေးဆွဲနေတဲ့ App ရဲ့ Database နဲ့ Code Structure သဘောတရားအရ "Reverse Entry" ခလုတ်ကို နှိပ်လိုက်ရင် နောက်ကွယ်က Data Flow ဟာ အောက်ပါအတိုင်း အလုပ်လုပ်သွားဖို့ တည်ဆောက်ရပါမယ်။

**Database Changes (လိုအပ်မည့် ပြောင်းလဲမှုများ):**
Transactions ဇယား (Table) တွင် မူလစာရင်းကို ဖျက်ခြင်း (Delete record) လုပ်မည့်အစား အချက်အလက်သစ်များ ဖြည့်စွက်ရပါမည်။
*   **Column အသစ်များ ထည့်ရန်:** `status` (ဥပမာ - Active, Reversed, Reversal) နှင့် `linked_transaction_id` (အချင်းချင်း ပြန်ချိတ်ဆက်ရန်)။

**Action ကို နှိပ်လိုက်ချိန် အလုပ်လုပ်မည့် Code Logic:**
1.  **Read Original:** မူလ Transaction (ဥပမာ - ID: t123) ၏ အချက်အလက်များ (Lines အားလုံး) ကို ဆွဲထုတ် (Fetch) ပါမည်။
2.  **Create Reversal Data:** 
    *   ID အသစ် (ဥပမာ - ID: t124) ဖန်တီးမည်။
    *   Date ကို ယနေ့ရက်စွဲ သတ်မှတ်မည်။
    *   Description တွင် "Reversed Entry of #t123" ဟု အလိုအလျောက် ရေးမည်။
    *   Lines များအားလုံးကို `map` ပတ်၍ `debit` ရှိသော တန်ဖိုးကို `credit` သို့၊ `credit` ရှိသော တန်ဖိုးကို `debit` သို့ ပြောင်းထည့်မည်။
3.  **Save to Database:** ထို Transaction အသစ် (t124) ကို စနစ်ထဲသို့ သိမ်း (Save) လိုက်ပါမည်။
4.  **Update Status:** မူလစာရင်း (t123) ၏ status ကို "Active" မှ "Reversed" ဟု ပြောင်းလိုက်ပြီး UI တွင် မှိန်ထားခြင်း (သို့) မျဉ်းခြစ်ပြထားခြင်း ဖြင့် အသုံးပြုသူကို အသိပေးပါမည်။

ဒီလို တည်ဆောက်ခြင်းအားဖြင့် App ရဲ့ General Ledger ကို တွက်ချက်တဲ့အခါ (t123) နဲ့ (t124) ဟာ အလိုအလျောက် အချင်းချင်း ကျေသွားပြီး Ledger Balance အမှန်ကို ရရှိစေမှာ ဖြစ်ပါတယ်။
